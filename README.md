# LevelUp — Forge 1.20.1

Java 17 / Forge 47.1.3 模组。把 `build/libs/levelup-1.0.0.jar` 放进服务端 mods；客户端装同一个 jar（事件 BGM 由客户端播放并接管原版音乐），单人游戏装到客户端即可。没装模组的客户端仍可正常进服，但听不到事件音乐，服务器日志会给出提示。使用原版 Boss 条。

## 配置

首次启动服务器或进入单人存档自动生成：

* `config/levelup-common.toml`：下界、末地血量/攻击最大倍率、护甲随机上限、独立速度倍率上限；经验倍率和上限；特殊日开关。
* `config/levelup/days.json`：特殊日定义。
* `config/levelup/loot.json`：加权奖励表，支持其他模组已注册的物品 ID。

示例位于 `config-examples/levelup/`。TOML 由 Forge 监视重载；修改 JSON 后执行管理员命令 `/levelup reload`。无效 JSON 拒绝重载，保留上一份有效规则，错误记录在服务器日志。首次加载失败时奖励与特殊日不可用，修正后重载即可。

## 维度强化

`netherMaxMultiplier` / `endMaxMultiplier` 范围 1～100。每只新生成的敌对 `Mob + Enemy` 生物抽取一个均匀随机倍率 `[1, 最大倍率)`，血量和攻击共用此倍率；设为 1 时血量/攻击不增幅，护甲/速度仍按以下规则设置。血量/攻击使用永久属性修饰符并补满生命。

`netherMaxArmor` / `endMaxArmor` 为随机基础护甲上限（0～30），默认均为 8；配置 8 时生成基础护甲随机取 `[0, 8)`，直接设置基础属性，不追加原基础值，原本零护甲也能获得护甲。上限为 0 时基础护甲固定为 0。

`netherMaxSpeedMultiplier` / `endMaxSpeedMultiplier` 为独立随机速度倍率上限（1～100），默认均为 1.25。生成时单独抽取 `1 + 随机数 × (配置值 - 1)`，例如 1.25 表示原速度随机增加 0～25%，1 表示不增幅；与血量/攻击倍率及护甲抽取相互独立。使用永久速度属性修饰符，不替换原基础速度。

旧速度配置键 `netherMaxMovementSpeed` / `endMaxMovementSpeed` 已停用，请使用上述新键填写倍率。

装备、效果及其他模组修饰符仍可影响最终属性，最终值尊重原版属性上限。已有怪物保留先前数值，新设置仅影响新生成怪物。

近战使用强化后的攻击属性；能够追踪到强化怪物的弹射物伤害也乘攻击倍率。无法归因的火焰/环境伤害和其他模组绕过攻击属性的特殊直伤不保证覆盖。

强化信息保存到实体 NBT，区块重载、服务器重启、跨维度不重复强化。旧存档的现有怪物不追溯强化。自然生成、刷怪笼、刷怪蛋、命令生成都包含。

## 特殊日

`days.json` 示例：

```json
{"days":[{"day":30,"probability":0.2,"repeatable":false,"title":"血月","announcement":"血月来临！","healthMultiplier":3,"attackMultiplier":2,"speedMultiplier":1.3,"armor":8,"lootTable":"wenwen","experienceMultiplier":1}]}
```

* `day`：参与每日抽取的最低天数，包含当天。世界时间 0～23999 为第 1 天；设为 30 时，第 1～29 天不参与，第 30 天起每天参与。
* `probability`：必填，每天独立抽中的概率，范围 0～1；0.2 表示 20%，0 表示永不抽中，1 表示达到天数后每天抽中。不是所有事件加起来必须等于 1。
* `repeatable`：布尔值，默认 `true`，允许在不同日期反复出现；`false` 表示只有实际被选中执行一次后才退出后续日期的抽取。未抽中、尚未达到天数、开关关闭，或抽中但被前面的事件占用，都不会消耗这次机会。当天事件仍正常持续到当天结束；同日重载或重启会恢复当天事件。
* `repeatEvery` 已移除；旧配置必须删除这个字段，并填写 `probability`，否则拒绝重载并保留原有效配置。想近似保留原平均频率，可将原来每 N 天一次改为 `probability: 1/N`，但不再保证固定间隔。默认生成的事件从第 7 天开始，每天有 15% 概率抽中，奖励表为 `wenwen`；示例文件的概率按旧周期的倒数设置，可自行调整。
* `title` / `announcement`：Boss 条标题、全服播报文本。
* `bossBarColor`：每个事件独立设置血条颜色，支持 `pink`、`blue`、`red`、`green`、`yellow`、`purple`、`white`（大小写均可），省略为 `red`。例如 `"bossBarColor": "purple"`。无效颜色会拒绝重载并保留原配置。
* `mobParticles`：是否显示该事件强化怪物的彩色粒子，省略为 `true`；粒子颜色跟随 `bossBarColor`。例如 `"mobParticles": false` 可关闭。

客户端安装 LevelUp 后，事件强化怪物身上会出现彩色粒子；再安装 Jade（Forge / Minecraft 1.20.1）后，看向怪物会显示「强化：事件名称」，名称取自 `title`。Jade 为可选模组，服务器无需安装 Jade。名称和粒子设置在怪物出生时保存，跨天、重载、区块重新加载和重启后仍保留原事件；升级前已经存在的怪物没有事件名称记录，不会猜测或补写名称。下界/末地的普通维度强化没有自定义事件名称，不显示此提示或事件粒子。

粒子采用参考项目 Champions 的八帧法术纹理、随机明暗、大小、生命周期和上浮散开运动参数。普通粒子模式每只怪物每 tick 最多一个粒子，与参考项目密度一致；怪物密集时总量上限会减少显示密度。

性能：仅开始追踪时向安装 LevelUp 的玩家同步一次怪物信息，不持续发送粒子包，不扫描世界或保存全局怪物列表。只显示 32 格以内、存活且非隐形的怪物，全客户端每 tick 最多 16 个粒子；原版「减少」模式每只怪物每 2 tick 最多一个，总量最多 8 个，「最少」模式关闭。Jade 直接读取已经同步的数据，无额外轮询请求。

`mobEffects`：每个事件可配置生成后直接赋予怪物的效果列表，省略或 `[]` 表示不赋予。例如：

```json
"mobEffects": [
  {"effect": "minecraft:fire_resistance", "durationSeconds": 600, "level": 1},
  {"effect": "minecraft:resistance", "durationSeconds": 120, "level": 2}
]
```

效果 ID 支持原版和已安装模组，最多 32 条；时长范围 1～86400 秒，默认 10 秒；等级范围 1～256，默认 1。只在事件期间新生成的主世界敌对怪物上施加一次，效果到期或被移除后不补充，跨天不移除；存档与剩余时长由原版保存，区块重载不重复施加。怪物对某效果免疫时遵循原版规则。瞬时效果只在生成时触发一次。新增功能没有怪物扫描或续期任务，但持续效果本身仍有原版或对应模组的执行开销。
* `healthMultiplier` / `attackMultiplier` / `speedMultiplier`：固定属性倍率（1～100）。
* `armor`：固定基础护甲（0～1000），装备和其他模组修饰符仍可增加最终护甲，受原版属性上限约束。
* `lootTable`：`loot.json` 中专属奖励表名称。
* `experienceMultiplier`：事件独立经验倍率（0～100，允许小数），省略时默认 1；与全局经验倍率相乘，设为 0 时该事件怪物完全不掉经验。
* `attackEffects`：攻击附加效果列表，省略或 `[]` 表示没有附加效果。默认自动生成配置使用空列表；项目示例展示中毒和缓慢。
* `playerEffects`：事件期间直接挂在玩家身上的效果列表（对所有在线玩家生效，含其它维度），省略或 `[]` 表示没有。与 `attackEffects` 不同，不需要怪物攻击：事件进行中每秒检查一次，玩家喝牛奶、`/effect clear`、死亡重生或效果快过期都会立刻重新施加；事件结束后停止施加，身上的效果在不超过 `durationSeconds` 内自然淡出。字段与 `attackEffects` 相同（`effect`、`durationSeconds`、`level`），每条最多 32 条，不接受瞬时效果（瞬间伤害/瞬间治疗之类没法「维持」）。
* `bgm`：事件音乐声音 ID，例如 `levelup:music.blood_moon`；省略或空字符串表示关闭。
* `bgmVolume`：音乐音量（0～1，默认 1），最终还受客户端主音量和“音乐”音量控制。
* `bgmDurationSeconds`：单次音乐实际长度，1～86400 秒，允许小数，默认 180；服务端按此时长循环播放，务必填写实际曲长。

例如在事件对象内加入：

```json
"attackEffects": [
  {"effect":"minecraft:poison","durationSeconds":10,"level":1},
  {"effect":"minecraft:slowness","durationSeconds":5,"level":2}
]
```

`playerEffects` 则是整场事件都挂在玩家身上的效果，例如让事件期间玩家持续缓慢并获得生命恢复：

```json
"playerEffects": [
  {"effect":"minecraft:slowness","durationSeconds":10,"level":1},
  {"effect":"minecraft:regeneration","durationSeconds":10,"level":1}
]
```

`durationSeconds` 是每次施加的时长；事件期间服务器在剩余时间不足一半时续期，所以效果会一直保持到事件结束。玩家身上已有更强的同类效果时不会被覆盖（例如事件施加力量 I 时玩家喝下力量 II，保留力量 II），效果结束后仍按配置施加。

`effect` 是注册效果 ID，支持原版和已安装模组的 `模组ID:效果ID`，必填；不存在的效果会拒绝整份 JSON 重载并保留旧规则。`durationSeconds` 为整数秒（1～86400，默认 10），按每秒 20 tick 换算；`level` 为实际等级（1～256，默认 1），1 表示 I 级、2 表示 II 级。每个事件最多 32 个效果。

当天生成的事件怪物每次实际造成正数生命伤害时，会向被击中的生物施加列表内全部效果；近战和能归因到怪物的弹射物都支持，不限于玩家目标。被取消的伤害、完全被盾牌挡住或被吸收生命完全抵消的攻击不触发。效果免疫和同类效果合并遵循原版及其他模组规则，重复攻击通常刷新持续时间，不会不断增加等级。瞬间效果立即生效，其持续时间不参与计算；瞬间效果引发的嵌套伤害不会再次递归触发附加效果。其他模组未提供来源怪物的伤害不能归因。

效果列表按注册名称保存到怪物 NBT，跨天、区块重载和重启仍保留；命中时使用弱引用缓存，效果仅在首次恢复该怪物列表时查注册表。移除模组后，已有怪物中找不到的效果跳过。修改后使用 `/levelup reload`，只影响之后新生成的事件怪物；旧版本怪物不追溯添加效果。

每天对所有达到 `day` 门槛的事件独立抽取一次。如果多个事件抽中，只执行数组中第一个抽中的事件；全部没抽中，当天没有事件。前面的事件有优先权，因此后面事件的实际执行概率可能低于它的 `probability`；前面配置概率为 1 的事件达到门槛后会挡住后面的事件。

当天结果缓存，怪物生成、Boss 条、玩家效果和音乐读取同一个结果，不会按怪物或每秒重新抽取。抽取使用世界种子与当天日期确定的随机序列，与怪物生成等游戏随机数独立；配置和顺序不变时，同一天重启、重载或 `/time` 回到该日仍得到相同结果。修改规则后重载会重新计算当天结果，可能切换事件。

执行记录随主世界保存到存档的 `data/levelup_events.dat`，不同存档互不影响。事件由 `day`、`title`、`lootTable` 三个字段共同识别；调整概率、属性、效果或数组顺序不会重置记录。修改这三个识别字段之一会视为新事件，三者完全相同的条目共享记录。已执行的一次性事件不会在其他日期再次参与抽取，包括用 `/time` 回退日期；若回到它原本执行的当天，会恢复该日事件。将已执行的事件从 `true` 改为 `false`，也会保留已有执行记录。升级前发生过的事件没有执行记录，从升级后开始记录。

当天在主世界新生成的敌对怪物获得抽中事件的强化；已有怪物不遍历、不追加强化。下界/末地仍使用各自规则。怪物保留强化和专属掉落，跨天也不撤销。

所有在线玩家看到播报和 Boss 条。进度直接读取主世界 `dayTime`，每秒刷新，持续到当天结束；睡觉跳过夜晚和 `/time` 跳时都会反映到进度，关闭日夜循环时进度暂停。加入的玩家一秒内显示，事件结束一秒内移除。重启/进入存档时若当天抽中了事件会播报一次；跨天时只抽取到达的当天，整个被跳过的日期不补执行事件。连续两天抽中同一个事件仍按新一天重新播报。

事件开始时向全服在线玩家发送 BGM 播放指令：走自定义网络包（`levelup:music` 通道），由装了本模组的客户端自己播放并接管原版背景音乐。晚加入玩家一秒内从头播放；重生/跨维度后从头播放。每位玩家按 `bgmDurationSeconds` 循环播放，直到事件结束、关闭或切换时停止对应声音。循环使用单调现实时间计时，不受睡眠跳时影响，也不因低 TPS 把歌曲长度拉长；每秒检查一次（20 tick），正常 TPS 下重播可能有不到一秒间隙，服务器卡顿时可能更长，不保证无缝衔接。停止事件仍以主世界时间判定，睡眠跳过事件结束会在下一次检查停止。

每次重播替换上一遍（客户端自己换实例），所以不用再单独发停止包。曲长配置过短会提前截断歌曲，过长会在两遍之间留下静音。音乐是非定位声音，走动不会远离声源。客户端背景音乐由原版 `MusicManager` 自行挑选，与本模组的声音互不知情，因此客户端收到播放指令后：先清空整条 MUSIC 音轨（原版背景音乐、其它模组的音乐和上一遍事件音乐一起停掉），再播放带 `bgmVolume` 音量的事件音乐，并在 `PlaySoundEvent` 里拦掉事件期间所有其它 MUSIC 声音，让原版背景音乐起不来；收到停止指令时停掉事件音乐，并主动让 `MusicManager` 立刻开始当前情境的原版音乐，所以事件结束后原版音乐立即恢复，不会出现原版那套 10～20 分钟的随机等待。播放器音量为 0 或客户端没有音频资源时听不到，服务器无法强制打开客户端音量，也无法确认资源包是否加载成功。服务端无法读取客户端音频曲长，所以必须手动配置。

`bgm` 填写 sounds.json 中的声音事件 ID，不是音频路径或文件名。可以使用原版声音（如 `minecraft:music_disc.13`）测试，无需任何音频文件；自定义音乐需要每个客户端都能读到音频文件（放进模组 jar 的 `assets/` 里，或让客户端启用独立资源包），只放在服务端磁盘上不会传到客户端。`config-examples/bgm-resourcepack/` 可作为独立资源包模板：补上 Ogg Vorbis 音频 `assets/levelup/sounds/music/blood_moon.ogg`，在事件配置填写 `"bgm":"levelup:music.blood_moon"`。sounds.json 使用 `stream:true`，长音频通过流式播放读取。

音频可以直接放进模组 jar：`src/main/resources/assets/<命名空间>/sounds/` 配合 `sounds.json`（本项目已把 `assets/levelup/sounds/music/level1~7.ogg` 与对应 `sounds.json` 放在这里，客户端装了模组就自带，无需额外资源包）。也可以做成独立资源包，由玩家手动启用，或把 ZIP 放在可下载地址并配置服务器 `server.properties` 的 `resource-pack` 和 `resource-pack-sha1`，由原版资源包流程下发（ZIP 根目录直接包含 `pack.mcmeta` 和 `assets`）。播放指令走自定义包，所以没装模组的客户端听不到事件音乐，单独下发资源包也没有意义；这类客户端仍可正常进服，服务器会为每位这样的玩家输出一行警告日志。没有提供客户端音频文件时只校验 ID 格式，不校验声音是否存在。修改 BGM 配置后 `/levelup reload` 会在下一次事件检查时切换音乐；替换音频文件后客户端还需要重载资源。

## 奖励表与经验

`loot.json` 结构：

```json
{"tables":{"dimension":[
  {"item":"minecraft:iron_ingot","count":1,"weight":100,"rarity":0,"minStrength":1},
  {"item":"minecraft:diamond","count":1,"weight":3,"rarity":3,"minStrength":2},
  {"blank":true,"weight":40,"rarity":0,"minStrength":1}
],"blood_moon":[
  {"item":"minecraft:gold_ingot","count":1,"weight":50,"rarity":0,"minStrength":1},
  {"item":"minecraft:diamond","count":1,"weight":5,"rarity":2,"minStrength":1}
]}}
```

玩家直接或使用弹射物击杀强化怪物时，在原掉落之外额外抽取一个条目，数量由 `count`（1～64）指定。遵守 `doMobLoot`，环境击杀不奖励。必须存在 `dimension` 表；每表至少有一个 `minStrength=1` 的条目，保证每次可抽中。非法物品 ID、空表或非法数值拒绝重载。

条目字段：`item` 物品 ID（必填，除非轮空）、`count` 数量（1～64，默认 1）、`weight` 基础权重（0.000001～1e9，默认 1）、`rarity` 稀有度（0～10，默认 0）、`minStrength` 抽取门槛（1～100，允许小数，默认 1）。省略字段就用默认值。

**轮空**（抽中后不掉任何额外物品）有两种写法，等价：

```json
{"blank":true,"weight":40,"rarity":0,"minStrength":1}
{"item":"minecraft:air","weight":40,"rarity":0,"minStrength":1}
```

轮空条目和普通条目一起参与加权抽取（`count` 对轮空无意义），也照样受 `minStrength` 门槛限制；`minStrength=1` 的轮空条目同样满足「每表至少一条可抽」的校验。想让某个表基本不掉额外物品，就把它调成一条高权重的轮空条目；整表只有轮空条目也合法（等于该事件永无额外掉落）。

**附魔书**：条目只写 `minecraft:enchanted_book` 就行，抽中后会自动带一条「宝藏附魔」——附魔台刷不到的那些：

```json
{"item":"minecraft:enchanted_book","count":1,"weight":3,"rarity":2,"minStrength":2}
```

* 候选池 = 全部已注册附魔里 `isTreasureOnly()` 的：原版是经验修补、冰霜行者、灵魂疾行、迅捷潜行，模组里标记为宝藏附魔的同样算；
* 诅咒（绑定诅咒、消失诅咒）虽然也算宝藏附魔，但不会当奖励发出来；
* 等级取该附魔自身的范围（经验修补必为 I，灵魂疾行 I～III 等），不会出现超等级；
* 均匀随机，写入正常的 `StoredEnchantments`，铁砧/砂轮与普通附魔书一致；
* 所以条目里不需要（也没有）任何附魔相关配置项。

维度强度为随机倍率。特殊日强度为 `max(1, (血量倍率 + 攻击倍率 + 速度倍率 + 1 + 护甲/20) / 4)`。

只有 `minStrength <= 强度` 的条目可抽取。实际权重为 `weight × 强度^rarity`，概率为实际权重占总权重的比例。稀有物品应配置较小 `weight`、较大 `rarity`（0～10）；强怪的稀有物品相对概率更高。`minStrength` 可限制弱怪掉落顶级物品。概率提高不意味着每只强怪必定掉更贵的物品。

经验为 `原经验 × 强度 × 全局 experienceMultiplier × 事件 experienceMultiplier`（最后四舍五入），受 `maxExperiencePerMob` 限制，默认 10000，避免极端设置产生大量经验球。下界/末地事件倍率视为 1。事件倍率设为 0 时原经验和加成经验都不掉落，物品奖励不受影响。经验玩家归因遵循原版近期玩家攻击规则；原经验为零仍为零。

事件倍率在怪物生成时保存，跨天、重启仍保留；修改 `days.json` 后执行 `/levelup reload`，新倍率仅影响之后生成的怪物。旧版本已生成且没有此字段的怪物按事件倍率 1 处理，兼容旧配置。全局经验倍率和上限在击杀时读取。

## 性能与验证

强化只在实体首次加入世界时执行，无每怪物 tick 逻辑。JSON 只在启动或手动重载时解析，原子切换不可变快照。每日事件抽取 O(事件条数)，当天查询缓存 O(1)；新一天、配置重载或开关变化时重新计算。击杀抽奖 O(表条目数)，Boss 条与玩家效果每秒 O(在线玩家数 × 效果条数)，不扫描怪物/区块、不强制加载区块。额外伤害检查仅在伤害事件执行。

Java 17 下运行 `./gradlew.bat build --offline`（本地依赖齐全时）。`check` 自动运行 11 项时间与数值边界检查，覆盖天数切换、睡眠跳时、稀有权重、经验溢出上限、事件与全局倍率叠加及事件零倍率。另有每日概率检查，覆盖最低天数、0/1 概率、抽中边界、多事件独立抽取与优先级、全部落空、长世界年龄、缓存空结果、跨天、重载、开关切换、重启结果一致，以及非法概率与旧字段拒绝。
另有重复开关与存档记录检查，覆盖布尔值校验、默认兼容、执行后排除、被优先级挡住不消耗机会、当天保持、记录序列化恢复、跨天与回退日期、配置重排，以及重复事件改为一次性后的记录保留。
另有 8 项攻击效果配置检查，覆盖旧配置兼容、秒数与等级换算、模组命名空间、未知效果、非法数值及效果数量上限。尚需游戏内验证真实效果注册、盾牌、效果免疫与弹射物命中。
另有 7 项掉落表抽取检查，覆盖 `minStrength` 门槛、等权重均分、`rarity` 随强度放大稀有物品概率、零权重不可抽中以及轮空条目参与抽取。真实物品堆、附魔书的宝藏附魔、`doMobLoot`、环境击杀与额外掉落仍需游戏验收。

另有 18 项玩家效果配置与保持检查，覆盖旧配置兼容、与攻击效果列表互不串台、字段默认值、未知效果、非法数值、数量上限、拒绝瞬时效果，以及「缺失就补、更强不覆盖、同级快过期才续期」的施加判断。事件期间保持、喝牛奶后重挂、死亡重生与事件结束后淡出仍需游戏验收。
另有 16 项 BGM 配置、循环调度与发包编解码检查，覆盖旧配置默认关闭、资源包声音 ID、默认音量、非法 ID/音量/时长、重播时刻边界、小数曲长、静音禁用以及播放/停止包的往返编解码。实际声音、资源包下载、自定义包收发、循环播放、事件结束、加入及切换维度仍需游戏验收。

游戏验收建议：下界/末地近战与弹射物、刷怪笼、区块重载、玩家与环境击杀；用 `day:30, probability:1` 验证第 29 天不触发、第 30 天触发（`/time set 696000`）；再验证概率 0、多事件优先级、同日重启、睡眠跳夜和多玩家加入退出。
